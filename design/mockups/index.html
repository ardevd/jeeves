JEEVES NEW — UI Design Mockups

Three candidate design philosophies for the next-generation Android reverse-engineering workbench. Background & competitive analysis: ../RESEARCH.md
Mockup A — Evolutionary

The Workbench

The familiar IDE shape, done right. Keeps the mental model every IDA/Ghidra/Binary Ninja user already has, and fixes the current Jeeves gap list.

  • Command palette as primary interface + hotkey hints everywhere
  • Unified back/forward navigation history across all views
  • Activity bar, method outline, selection-synced xref panel
  • Agent presence integrated but secondary (toast → review)

Best for: adoption — lowest relearning cost, fastest to build on the existing backend.

 Mockup A2 — Evolutionary, multi-target

The Workbench, v2

The Workbench with the open questions resolved: concurrent research targets, pluggable engines, nameless identity. This is the current design baseline.

  • Browser-style target strip — same artifact open in two engines as two targets
  • Engine capability chips; UI degrades per engine (JEB / JADX / IDA)
  • Per-target + global heap gauges in the status bar
  • Nameless: phosphor hex-print favicon instead of a brand; top bar shows a location breadcrumb
  • Java | Smali | Split view modes with cursor-synced panes (Tab to cycle)

Best for: the build target — this is what v1 implements.

 Mockup S — Surface view

Strings View

The DEX strings table promoted to a full surface (not an overlay): heuristic type classification, live filtering, and an xref preview panel per string.

  • Type chips (URL / crypto / intent / permission / content-uri / base64? …), multi-select filtering
  • Unreachable-only and reachable-from-selection filters
  • Row selection → full string + xref list + jump-to-first-use in the preview rail

Best for: triage — the fastest way to find interesting threads to pull on.

 Mockup B — Radical

The Investigation Board

Graph-first. The source→sink evidence graph is the home screen; code is a detail panel you drill into. Flows, hypotheses and open questions are first-class objects on the canvas.

  • Static / low-confidence-hub / runtime-observed edges distinguished visually
  • Pinned hypothesis notes tethered to nodes
  • Investigation outline: flows, hypotheses, open questions
  • Node detail rail with code excerpt, xrefs, runtime sparkline

Best for: campaign-style research — "how does data move through this app".

 Mockup C — AI-first

The Agent Cockpit

Missions (agent runs) are the primary objects; the human supervises. Review queue of agent-proposed renames/comments as inline ghost diffs, live multi-agent activity stream, budget and write-scope controls.

  • Accept/reject each proposed edit in place (⌘A / ⌘X)
  • Per-mission model, token budget, write-scope enforcement with visible blocks
  • Local-model support for confidential samples
  • Extends what current Jeeves uniquely already has (co-presence, headless runs)

Best for: scale — fleets of agents do the grunt work, the analyst keeps judgment.
These are static single-file mockups (no backend). Interactions are simulated with inline JS. The philosophies are not mutually exclusive — a real product could ship A as the base shell, with B and C as first-class views inside it.
